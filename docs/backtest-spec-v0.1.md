# Backtest Spec v0.1

本文件定義 `Market Direction Model v0.1` 的第一版回測方式。

## 目的

回測分成兩層：

1. **先驗證 Market Score 是否真的具有方向判斷能力。**
2. **再模擬如果依照分數操作，策略績效是否合理。**

第一層比第二層更重要。若 Market Score 本身無法將未來報酬有效排序，即使某段期間策略剛好賺錢，也不能視為模型有效。

---

# 1. 訊號時間與可操作時間

## 訊號時間

每天收盤後，等待當日所需的 TWSE / TAIFEX 資料均已公布後，產生當日 `Market Score`。

## 可操作時間

當日收盤後才知道的訊號，最早只能從 **下一個交易日**開始生效。

不得假設在資料尚未公布前就已知道當日最終分數。

這是避免 Look-ahead Bias 的基本規則。

---

# 2. 第一層：驗證 Market Score 的預測／排序能力

對歷史上的每一個交易日 `t`：

```text
Market Score_t
    ↓
觀察未來報酬
```

## Forward Return

主要觀察：

- **未來 10 個交易日報酬**：Primary

輔助觀察：

- 未來 5 個交易日報酬
- 未來 20 個交易日報酬

初步可使用 TAIEX 作為市場方向驗證標的；若後續建立實際交易策略，則可另使用台指期近月連續序列進行交易層回測。

## 分數分組

將每日 Market Score 分為五組：

所有分組均含下界、不含上界；最高組包含 100。分數 20、40、60、80 分別歸入以該分數為下界的組別，因此五組互斥且完整涵蓋 0–100。後續表格與報告範本都沿用此規則。

| Market Score | 模型判斷 |
|---:|---|
| [80, 100] | 強多 |
| [60, 80) | 偏多 |
| [40, 60) | 中性／觀望 |
| [20, 40) | 偏空 |
| [0, 20) | 強空 |

對每組計算：

- 樣本數
- 未來 5 日平均報酬
- 未來 10 日平均報酬
- 未來 20 日平均報酬
- 報酬中位數
- 上漲比例
- 報酬分布

## 第一層最重要的判斷

理想情況應該看到：

```text
低分區間 → 未來報酬較差
中間區間 → 接近中性
高分區間 → 未來報酬較好
```

也就是 Market Score 越高，未來平均報酬應大致越高。

我們特別重視 **單調性（monotonicity）**，而不是只看單一命中率。

例如理想結果：

| 分數區間 | 未來10日平均報酬 |
|---|---:|
| [0, 20) | -3.0% |
| [20, 40) | -1.2% |
| [40, 60) | +0.1% |
| [60, 80) | +1.3% |
| [80, 100] | +2.8% |

上述數字僅為示意，不是預設目標值。

---

# 3. 第二層：策略回測

只有在第一層確認 Market Score 有一定排序能力後，才進一步測試「真的照分數操作」會怎麼樣。

## v0.1 部位規則

| Market Score | 模擬部位 |
|---:|---:|
| [80, 100] | +100% 多方 |
| [60, 80) | +50% 多方 |
| [40, 60) | 0%，觀望 |
| [20, 40) | -50% 空方 |
| [0, 20) | -100% 空方 |

例如：

```text
今天收盤後 Score = 75
→ 下一個交易日起採 +50% 多方部位
```

若下一次訊號變成：

```text
Score = 48
→ 下一個交易日降為 0%
```

此規則只是 v0.1 的基準策略，之後可測試不同門檻與部位配置，但不可為了把歷史績效調漂亮而無限制微調。

---

# 4. 策略績效指標

第二層至少計算：

- 累積報酬
- 年化報酬
- 最大回撤（Max Drawdown）
- Sharpe Ratio
- 勝率
- 平均獲利
- 平均虧損
- 多方訊號後平均報酬
- 空方訊號後平均報酬
- 交易／換倉次數

並與基準比較：

- Buy & Hold TAIEX
- 若使用期貨策略，另建立合理的期貨基準

後續若進入可交易策略階段，需加入：

- 手續費
- 交易稅
- 滑價
- 期貨換月成本

v0.1 的模型有效性驗證可先不讓交易成本干擾第一層的 Factor / Score 判斷。

---

# 5. 嚴格避免 Look-ahead Bias

任何歷史日期只能使用當時已經知道的資料。

例如在回測 `2021-06-01` 的 Market Score 時，如果某因子使用「過去 3 年歷史百分位」，只能使用當日以前的歷史資料。

```text
允許：2018-06-01 ～ 2021-05-31
禁止：使用 2021-06-01 之後的資料決定 2021-06-01 的百分位
```

因此歷史百分位應採用 rolling / expanding 的方式計算，不能先用整份 10 年資料一次算好再回填到過去。

---

# 6. 避免 Overfitting

目前 8 個因子與權重是人工建立的 v0.1 初始假設：

```text
MA20 / MA60 趨勢            20%
20日動能                    10%
外資5日買賣超               15%
外資台指期淨多空部位        15%
外資期貨淨部位5日變化       10%
期現貨價差 Basis             5%
OI Put/Call Ratio           10%
Taiwan VIX                  15%
```

回測結果不好時，可以有理由地調整模型，但不能反覆把權重調到歷史績效最好看。

建議後續採：

```text
開發區間
→ 建立／調整模型

驗證區間
→ 確認規則是否仍成立

Out-of-Sample 區間
→ 最後一次測試，開發過程不使用
```

資料量足夠後，再升級成 Walk-forward Backtest。

---

# 7. 回測期間

資料來源允許的情況下，目標使用 **8～10 年**歷史資料。

回測期間應盡量包含：

- 多頭市場
- 空頭市場
- 盤整市場
- 高波動期
- 低波動期
- 快速反轉期

若某個因子的官方歷史資料不足 8～10 年，則必須記錄實際可用期間，並避免因不同因子的資料長度而產生不一致樣本。

---

# 8. Backtest v0.1 成功標準

第一版不預設「年化報酬一定要達到多少」。

模型先滿足以下三個核心條件：

1. **[80, 100] 分區間的未來平均報酬明顯高於 [0, 20) 分區間。**
2. **五個分數區間的未來報酬大致具有單調性。**
3. **上述現象在 5、10、20 日與不同市場環境中仍大致存在。**

若這三點不成立，優先重新檢查：

- 因子方向是否錯誤
- 指標是否重複
- 百分位轉換是否合理
- PCR 等非線性因子的定義
- Basis 是否需要除息／到期修正
- 權重是否需要調整
- 某些因子是否應直接移除

而不是直接進入網站美化或實盤使用。

# 9. v0.1 回測輸出

最終回測頁／報告至少應能輸出：

```text
Model version: v0.1
Backtest period: YYYY-MM-DD ~ YYYY-MM-DD
Primary horizon: 10 trading days

Score Bucket     Avg 5D     Avg 10D     Avg 20D
[0, 20)           ...        ...          ...
[20, 40)          ...        ...          ...
[40, 60)          ...        ...          ...
[60, 80)          ...        ...          ...
[80, 100]         ...        ...          ...
```

以及策略層：

```text
Annualized Return
Max Drawdown
Sharpe Ratio
Win Rate
Buy & Hold Comparison
```

## 實作現況（2026-09-17）：第一層引擎已完成，尚未有足夠真實資料可產出正式結論

第一層回測引擎已實作於 `src/backtest/layer1.py`，並提供 CLI 入口
`scripts/run_backtest_layer1.py`：

- `build_score_series` 對回測區間內每一個有 TAIEX 收盤的交易日重播
  `calculate_daily_score`，歷史百分位一律由 `src/scoring/history.py` 的
  `build_historical_values` 依當天以前的資料現算，不會用整段期間一次算好再回填
  （符合第 5 節的 rolling/expanding 要求）。
- `compute_forward_returns` 以 TAIEX 收盤序列本身的交易日順位計算未來 5／10／20
  日報酬，作為驗證用的結果標籤；資料不足以支撐某個窗口時明確回傳 `None`，不用
  外插值頂替。
- 第一層的 forward return 是**排序驗證標籤**，不是交易層的成交報酬：以訊號日收盤
  `close_t` 為分母、以第 `h` 個後續交易日收盤 `close_{t+h}` 為分子。這讓分數與
  結果標籤的錨點固定且可重現；真正策略回測仍須遵守第 1 節，將訊號延到下一個交易日
  才生效。`run_backtest_layer1` 的 CLI 會在指定報告終點後多載入每個 horizon 的
  7 倍曆日，避免資料查詢範圍提前截斷最後幾個 forward labels；標籤本身仍只按實際
  TAIEX 交易日列計算。
- `summarize_buckets` 把每日分數依 `src.scoring.contracts.classify_score`
  （與正式評分同一個函式，不重新定義門檻）分入五組，計算樣本數、平均／中位報酬
  與上漲比例；`unavailable` 的日子不會被計入任何一組。
- `Layer1Report.is_monotonic()` 檢查平均報酬是否由低分組到高分組遞增；少於兩組
  有樣本時明確回傳「無法判斷」，不會假裝有結論。
- 輸出 JSON 除了分組統計，也保留每個訊號日的 `daily_rows`（狀態、分數、缺少的
  因子與各 horizon 報酬），方便追溯資料品質。沒有 TAIEX 收盤或沒有完整分數的日子
  不會補成中性；空資料會產生零樣本、各組統計為 `null`，單調性回傳無法判斷，不能
  被引用為模型有效性的證據。

**一個重要的語意差異**：這個引擎不把 bulk backfill 的
`retrieved_at`／`ingested_at` 當成歷史知識邊界，因為它們記的是「回補當下」（例如
2026-09），不是「歷史上那一天真的知道」。每個訊號日會建立自己的資料快照：必須
符合 `observation_date <= target_date`；若列有 `published_at`，也必須是 target date
當日或以前。沒有 `published_at` 的回補列才採 observation date fallback。如此既不會
因回補時間把全部歷史資料判成不可用，也不會讓 target date 之後才發布的修訂滲入舊
訊號。Forward label 則使用整段資料選出的最終價格版本，代表事後已知的實現報酬，
與當日 score 的歷史版本刻意分離。

**目前仍缺的是資料，不是程式**：8 個核心因子的官方資料共同起點目前仍卡在
Taiwan VIX／法人期貨 OI 的 ~2023-09（見
[`data-window-policy-v0.1.md`](data-window-policy-v0.1.md)），且一次性回補
（`scripts/backfill_taifex_*_range.py`）尚未實際對正式 Supabase 執行。因此本文件
第 8 節的三個成功標準（高分組是否明顯優於低分組、五組是否大致單調、是否跨
5／10／20 日與不同市場環境成立）都還沒有真實資料可以驗證；`run_layer1_backtest`
只用合成資料端對端測過管線本身的正確性（見 `tests/test_backtest_layer1.py`），
還沒有得出任何關於模型是否有效的結論，也不應該被引用為模型驗證結果。

實際執行一次性回補、讓每日 collector 持續累積之後，才能用
`python -m scripts.run_backtest_layer1 --start-date ... --end-date ...`
對真實資料跑出本文件第 9 節格式的正式報告。
